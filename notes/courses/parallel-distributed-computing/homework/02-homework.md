## 题目一（理解Attention与FlashAttention）

### (1) HBM访存量表达式及具体数值

设序列长度 \(N\)，头维度 \(d\)，FP16 精度每元素 2 字节。  
标准 Attention 需存储中间矩阵 \(S\) 和 \(P\)，其 HBM 访存包括：  
- 读 \(Q, K, V\)：\(3Nd\) 个元素  
- 写 \(S\)：\(N^2\) 个元素  
- 读 \(S\)：\(N^2\) 个元素  
- 写 \(P\)：\(N^2\) 个元素  
- 读 \(P\)：\(N^2\) 个元素  
- 写 \(O\)：\(Nd\) 个元素  

总元素数：  
\[
4N^2 + 4Nd
\]  
字节数（每元素 2 字节）：  
\[
M_{\text{std}} = 2(4N^2 + 4Nd) = 8N^2 + 8Nd
\]

FlashAttention 分块计算，避免将 \(N\times N\) 矩阵写回 HBM，仅需：  
- 读 \(Q, K, V\)：\(3Nd\) 个元素  
- 写 \(O\)：\(Nd\) 个元素  

总元素数：  
\[
4Nd
\]  
字节数：  
\[
M_{\text{flash}} = 2 \cdot 4Nd = 8Nd
\]

代入 \(N=4096,\ d=64\)：  
\[
M_{\text{std}} = 8 \times 4096^2 + 8 \times 4096 \times 64 = 8 \times 16\,777\,216 + 8 \times 262\,144 = 134\,217\,728 + 2\,097\,152 = 136\,314\,880\ \text{字节}
\]  
\[
M_{\text{flash}} = 8 \times 4096 \times 64 = 8 \times 262\,144 = 2\,097\,152\ \text{字节}
\]  
节省的 HBM 访存量：  
\[
\Delta M = M_{\text{std}} - M_{\text{flash}} = 136\,314\,880 - 2\,097\,152 = 134\,217\,728\ \text{字节} \approx 128\ \text{MB}
\]

### (2) 序列长度扩大到 \(4N\) 后的倍数变化

- **标准 Attention**：\(M_{\text{std}} \approx 8N^2\)（主导项），  
  增大倍数：\(\dfrac{8(4N)^2}{8N^2} = 16\) 倍。

- **FlashAttention**：\(M_{\text{flash}} = 8Nd\)，  
  增大倍数：\(\dfrac{8 \cdot (4N) \cdot d}{8N d} = 4\) 倍。

## 题目二：SM 线程块分配可行性及占用率

### (a) 计算能力 1.0

- 每 SM 最大线程块数：8，分配 8 块 → 块数可行
- 每 SM 最大并发线程数：768，实际线程数 = 8 × 128 = 1024 > 768  
  **不可行**，限制因素：**每 SM 最大并发线程数**（超出 256 线程）

### (b) 计算能力 1.2

- 每 SM 最大线程块数：8，分配 8 块 → 块数可行
- 每 SM 最大并发线程数：1024，实际线程数 = 8 × 128 = 1024 ≤ 1024
- 每 SM 最大 Warp 数：32，实际 Warp 数 = 8 × (128/32) = 8 × 4 = 32 ≤ 32
- 寄存器：未指定每线程寄存器用量，假设不超过每线程最大 128；每 SM 寄存器总数 16K，若每线程用 r 个，则 1024r ≤ 16384 → r ≤ 16，典型用法可满足
- 共享内存：未指定使用量，假设 0

**可行**，SM 占用率 = 实际线程数 / 最大并发线程数 = 1024 / 1024 = **100%**

### (c) 计算能力 3.0

- 每 SM 最大线程块数：16，分配 8 块 → 块数可行
- 每 SM 最大并发线程数：2048，实际线程数 = 1024 ≤ 2048
- 每 SM 最大 Warp 数：64，实际 Warp 数 = 32 ≤ 64
- 寄存器：每 SM 寄存器总数 64K，每线程最大 63，若每线程用 63 个寄存器，则总需求 = 1024 × 63 = 64512 < 65536，可行
- 共享内存：未指定使用量，假设 0

**可行**，SM 占用率 = 1024 / 2048 = **50%**

## 题目三（理解 Tensor Core）

### (1) FMA 总次数与指令条数

矩阵规模：\(256 \times 256\)，FP16 精度。  
输出矩阵 \(C\) 共 \(256 \times 256 = 65536\) 个元素，每个元素需 256 次乘加（内积）。  
总 FMA 运算次数：  
\[
N_{\text{FMA}} = 256 \times 256 \times 256 = 16\,777\,216
\]

#### SIMT 实现
每个线程计算一个输出元素，每个 FMA 由一条标量乘加指令完成。  
指令条数 = 总 FMA 次数 = **16\,777\,216 条**

#### Tensor Core (WMMA) 实现
每条 `mma_sync` 指令完成 \(16 \times 16 \times 16 = 4096\) 次 FMA。  
所需指令条数：  
\[
\frac{16\,777\,216}{4096} = 4096 \text{ 条}
\]

**指令层面效率优势**：  
Tensor Core 将 4096 次 FMA 合并为一条指令，指令条数减少为原来的 \(1/4096\)，大幅降低指令发射、解码和调度开销，提高吞吐量。

### (2) 硬件执行单元的角度

- **SIMT 核心**：每个 CUDA 核心含一个标量 FMA 单元，每时钟周期只能执行一次乘加。完成 4096 次 FMA 需要至少 4096 个时钟周期（理想流水线下），且受限于线程调度和访存。
- **Tensor Core**：专用硬件单元，内部包含**脉动阵列**或**乘法器树**，可在**一个时钟周期内**并行完成 \(16 \times 16 \times 16\) 的矩阵乘加运算（即 4096 次 FMA）。它利用数据复用和流水线，直接对矩阵分块做融合乘加，无需逐个标量操作。

因此，Tensor Core 能在更少时钟周期内完成相同计算，原因在于：
1. **更高并行度**：单周期内并行执行数千个乘加。
2. **专用数据通路**：减少寄存器读写和指令开销。
3. **计算与访存重叠**：配合 warp 级矩阵分片加载，隐藏访存延迟。
