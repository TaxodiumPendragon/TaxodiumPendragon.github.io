本讲我们将通过四个经典的并行计算模式，深入剖析 CUDA 编程的核心概念与优化技巧。这四个实例分别是：归约（Reduction）、扫描（Scan，也称前缀和）、直方图（Histogram）和可分离卷积（Separable Convolution）。通过对这些范例的分析与代码解读，我们将具体地理解线程协作、共享内存、bank 冲突、warp 分化、原子操作、纹理内存以及分块（Tiling）等关键技术。

## 第一部分：归约（Reduction）

归约的目标是将一个包含 N 个元素的数组，通过一个满足结合律的二元操作（如求和、求最大/最小值、求积），合并成一个单一的值。

一个简单直观的并行思路是，让 N 个线程同时启动，每个线程读取数组中的一个元素，然后通过一个原子加操作 `atomicAdd()` 将其累加到一个全局的内存地址上。这种方法虽然能保证结果的正确性，但却引入了严重的性能瓶瓶颈。因为 `atomicAdd()` 会对目标内存地址进行锁定，导致所有 N 个线程实际上是在这个单一地址上进行了串行化操作，完全丧失了 GPU 的并行优势。当 N 很大时，其性能甚至可能不如 CPU 上的简单循环。

高效的 GPU 归约算法采用的是基于树形的并行归约策略。其核心思想是分而治之，将大规模的全局归约问题分解为多个小规模的、在线程块（Block）内部完成的局部归约，最后再将各个块的局部结果进行最终的归约。

具体步骤如下：
1.  **块内归约**：将整个 N 元素的数组在逻辑上切分为多个块，每个线程块负责处理其中的一小块数据。首先，块内的每个线程从全局内存中读取一个元素，并载入到该线程块的共享内存（Shared Memory）中。接着，在共享内存上进行树形的归约操作。例如，在一个包含 256 个线程的块中，第一轮让前 128 个线程分别与后 128 个线程的对应元素相加；第二轮让前 64 个线程进行类似操作，以此类推。经过 log₂(256) = 8 轮迭代后，块内的所有元素之和就集中在了共享内存的第一个位置上。
2.  **写回部分和**：每个线程块完成局部归约后，由块内的第 0 号线程将该块的局部归约结果（即共享内存的第一个元素）写回到全局内存的一个预先分配好的部分和数组中。
3.  **最终归约**：当所有线程块都执行完毕后，我们得到一个包含了所有块的部分和的较小数组。此时，可以在 CPU 上对这个小数组进行最终的求和，或者启动第二个规模小得多的 CUDA 核函数来完成最后的归约。

这种树形归约算法的并行深度（即关键路径长度）为 O(log N)，而总工作量为 O(N)，相比于 `atomicAdd` 的 O(N) 深度，实现了巨大的性能提升。

### 归约的优化细节

实现高效的树形归约，需要深入理解并应用以下几个关键的优化技巧。

**优化一：线程协作与同步**
树形归约依赖于线程块内部的线程协作。这种协作通过共享内存显式地进行，其模式遵循一个严格的“写-同步-读”范式。
*   **加载阶段**：每个线程从全局内存读取一个元素，并写入共享内存的对应位置。
*   **同步**：在所有线程完成写入后，必须调用 `__syncthreads()`。这是一个块内同步栅栏，它会阻塞所有线程，直到块内*所有*线程都到达这个点，才能继续执行。这一步是强制性的，它确保了在进入下一阶段的读取操作时，共享内存中的所有数据都已准备就绪。若缺少同步，可能会发生读后写（RAW）冒险，即某个线程读取了另一个线程尚未写入的旧数据，导致结果错误。
*   **归约循环**：在每一轮归约中，一个线程会读取另一个线程在前一轮写入共享内存的结果。为了保证每一轮归约的正确性，在每一轮的加法操作之后，都必须再次调用 `__syncthreads()`，以确保在进入下一轮（步长更小的）归约之前，当前轮次的所有计算结果都已对块内所有线程可见。

**优化二：利用共享内存**
共享内存是位于每个流式多处理器（SM）片上的高速 SRAM，其访问延迟大约在 20-40 个时钟周期，而访问全局 DRAM 的延迟则高达约 600 个周期。在归约算法中，若不使用共享内存，每一轮的加法操作都将是一次缓慢的全局内存读写。而通过将数据预取到共享内存，所有的 log₂(BlockSize) 轮中间归约步骤都得以在片上高速完成，全局内存只在初始时被读取一次，以及在最后写回部分和时被写入一次，极大地减少了对内存带宽的压力。

共享内存的声明方式有静态和动态两种。静态方式在编译时确定大小，而动态方式 `extern __shared__ int sdata[];` 允许在核函数启动时，通过第三个尖括号参数动态指定每个线程块所需的共享内存大小。动态分配更为灵活，但也需要注意，每个 SM 的共享内存总容量是固定的。分配给每个块的共享内存越多，一个 SM 能同时容纳的活跃线程块就越少，这可能会影响到 GPU 通过调度更多 Warp 来隐藏延迟的能力，即占用率（Occupancy）会降低。这是一个需要在性能和资源之间进行权衡的决策。

**优化三：避免 Bank 冲突**
为了支持高并发访问，共享内存被划分为 32 个存储体（Bank）。连续的 4 字节字（word）被映射到连续的 Bank 上。例如，`sdata[0]` 在 bank 0，`sdata[1]` 在 bank 1，...，`sdata[31]` 在 bank 31，而 `sdata[32]` 则回到 bank 0。如果同一个 Warp 内的多个线程同时访问了同一个 Bank 的*不同*地址，就会发生 Bank 冲突，硬件会把这些访问串行化，造成延迟。

在一个朴素的、步长从 1 开始按 2 的幂次增长的归约算法中，当步长 `s` 达到 16 时，一个 Warp 内的线程（tid = 0...31）访问的地址索引将是 `2*s*tid`，即 0, 32, 64, ...。这些地址全部都映射到了 Bank 0，造成了严重的 16-way Bank 冲突。

我们在示例代码中采用的“逆向减半步长”策略（`s = blockDim.x / 2; s > 0; s >>= 1`）则巧妙地避免了这个问题。在这种模式下，一个线程 `tid` 读取的是 `sdata[tid+s]` 的值。当步长 `s` 很大时（例如 128），`tid` 和 `tid+s` 几乎总是在不同的 Bank。随着 `s` 减小，访问的地址间隔也随之减小，但由于 `s` 总是小于 Warp 的大小（32），并且是 2 的幂，`tid` 和 `tid+s` 的 Bank 索引的差值 `s % 32 = s`，因此它们永远不会访问到同一个 Bank（除非发生广播）。这样就保证了在整个归约过程中都不会发生 Bank 冲突。

**优化四：消除 Warp 分化**
Warp 分化发生于同一个 Warp 内的 32 个线程因为条件判断而走向了不同的执行路径。硬件会串行化地执行这两条路径，并屏蔽掉非活跃的线程，从而导致性能下降。

在朴素的归约算法中，通常使用 `if (tid % (2*s) == 0)` 来决定哪些线程在当前轮次执行加法。当 `s=1` 时，Warp 0 中的奇数线程和偶数线程就会走向不同分支，产生分化。

而在我们优化的版本中，执行加法的条件是 `if (tid < s)`。当步长 `s` 从 `blockDim.x / 2` 开始减半时，所有执行加法操作的线程（`tid` 从 0 到 `s-1`）是连续排列的，而不执行操作的线程（`tid` 从 `s` 到 `blockDim.x-1`）也是连续排列的。这意味着，一个 Warp 要么是完全活跃的（当 `s` 远大于 32 时），要么是完全不活跃的，不存在一个 Warp 内部分线程活跃而另一部分不活跃的情况，从而完美地消除了 Warp 分化。

作为一项额外的优化，当归约的步长 `s` 小于等于 32 时，所有活跃的线程都已位于同一个 Warp 内部。由于 Warp 内的执行是隐式同步的，此时不再需要调用 `__syncthreads()`，可以手动展开最后几轮循环以进一步提升性能。

## 第二部分：扫描（Prefix Sum）

扫描，或称前缀和，是另一个基础的并行计算原语。其目标是对于一个输入数组 `[x₀, x₁, x₂, ...]`，计算出其包含前缀和的输出数组。扫描分为两种：
*   **Inclusive Scan**: `[x₀, x₀+x₁, x₀+x₁+x₂, ...]`
*   **Exclusive Scan**: `[0, x₀, x₀+x₁, ...]`

扫描在许多并行算法中都有广泛应用，如基数排序、流压缩等。

### Hillis-Steele 扫描算法

这是一种经典的并行扫描算法，其思想非常直观。算法进行 log₂(N) 轮迭代。在第 `k` 轮（步长 `stride = 2^(k-1)`），每个线程 `j` 会读取 `data[j-stride]` 的值，并将其加到 `data[j]` 上。为了避免读写冲突，通常使用“乒乓缓冲”（ping-pong buffering）技术，即在两块共享内存缓冲区之间交替读写。

Hillis-Steele 算法的并行深度为 O(log N)，非常适合并行执行。但它的总工作量是 O(N log N)，因为每一轮迭代都有近 N 个线程在工作。相比之下，串行算法的工作量仅为 O(N)。这种“工作效率低下”的特性意味着，当 N 很大时，尽管并行度高，但由于执行了过多的冗余计算，其总耗时可能会很长。

### 工作高效的扫描算法

一种更优的扫描算法是基于归约的。它包含两个阶段：
1.  **上行阶段（Up-sweep/Reduction）**：这个阶段的结构与我们之前讨论的并行归约完全相同。通过树形相加，计算出一个包含各层级部分和的“和树”。
2.  **下行阶段（Down-sweep）**：从树的根节点开始，向下遍历。每个节点将其从父节点（在 Exclusive Scan 中，根节点的值为 0）继承来的前缀和，传递给其右子节点，并与其左子节点的局部和相加后传递给左子节点。当遍历完成后，叶子节点就包含了最终的前缀和。

这个算法的总工作量是 O(N)（上行和下行各约 N 次加法），并行深度为 O(log N)。它在理论上是工作高效的。

在实际应用中，两种算法各有优劣。当数据规模 N 较小，而硬件并行度非常高时，逻辑更简单的 Hillis-Steele 算法可能因其更高的指令级并行性而表现更佳。而当 N 很大，总计算量成为瓶颈时，工作高效的算法则会胜出。

## 第三部分：直方图

直方图算法的目标是统计输入数组中每个值出现的频率。在并行化时，其核心挑战在于处理对同一个“桶”（bin）的并发更新所引发的竞争条件。

**方案一：全局原子操作**
最直接的方法是为每个输入元素启动一个线程，该线程读取元素值 `k`，然后使用 `atomicAdd(&histo[k], 1)` 来对相应的桶进行原子递增。如前所述，这种方法在数据存在倾斜（即很多线程更新同一个桶）时会因全局内存争用而导致性能急剧下降。

**方案二：共享内存私有化**
一种高效得多的策略是利用共享内存来减少全局争用。
1.  **初始化**：在每个线程块内，声明一个大小为桶数量的共享内存数组，作为该块的“私有”直方图，并由块内线程并行地将其初始化为 0。
2.  **块内累积**：块内的每个线程负责处理输入数据的一个子集。线程读取一个数据 `k`，然后使用*共享内存原子操作* `atomicAdd(&s_histo[k], 1)` 来更新私有直方图。共享内存原子操作的延迟远低于全局原子操作（约 20 周期 vs 600 周期）。
3.  **全局合并**：当块内所有线程都处理完自己的数据后（需要 `__syncthreads()` 同步），块内线程再次协作，将私有直方图 `s_histo` 中的计数值，通过全局原子操作 `atomicAdd`，累加到最终的全局直方图 `histo` 中。

这种“私有化”策略的优势在于，它将大量的、可能高度冲突的原子操作限制在了每个块内部的高速共享内存中。只有在最后合并阶段，才会发生对全局内存的原子访问，并且访问的总次数被大幅减少到 `num_blocks * num_bins` 次，极大地缓解了争用。为了进一步优化，输入数据的读取也应该设计成合并访问模式，例如让一个块的线程连续读取一块连续的输入数据。

## 第四部分：卷积

卷积是图像处理和深度学习中的核心操作，它计算一个输出像素作为其邻域输入像素的加权和。

**朴素并行方法**：为每个输出像素分配一个线程。该线程循环读取其感受野内的所有输入像素和对应的卷积核权重，进行乘加运算。这种方法的瓶颈在于内存带宽，因为相邻的输出像素会重复读取大量相同的输入像素，造成了严重的访存冗余。

**优化一：分块（Tiling）与共享内存**
为了解决访存冗余，我们采用分块策略。
1.  **加载输入块**：让一个线程块负责计算输出图像的一个小“块”（Tile）。这个块内的所有线程首先协作，从全局内存中将计算该输出块所需的所有输入像素（包括为了处理边界所需的“光环”或“鬼影”单元，halo/ghost cells）一次性加载到共享内存中。
2.  **块内计算**：在数据加载完毕并同步后 (`__syncthreads()`)，每个线程再从高速的共享内存中读取输入像素进行卷积计算。

通过分块，原本需要被重复访问多次的全局内存数据，现在只需被加载一次，之后在共享内存中被块内所有线程高效地复用。这极大地提高了计算访存比（Arithmetic Intensity），是卷积乃至所有模板类（stencil）计算最重要的优化手段。

**优化二：利用常数内存和纹理内存**
*   **常数内存（Constant Memory）**：卷积核的权重对于所有线程来说都是不变的。将这些权重存储在常数内存中是绝佳的选择。常数内存是只读的，并且有专门的缓存。当一个 Warp 内的所有线程访问同一个常数内存地址时，会触发一次高效的广播。
*   **纹理内存（Texture Memory）**：对于输入图像数据，使用纹理内存也是一种有效的优化。纹理内存拥有为 2D 空间局部性优化的专用缓存。即使访问模式不是完全合并的（例如在可分离卷积的列处理阶段），纹理缓存也能有效地预取相邻像素，从而提升性能。此外，纹理硬件还提供了自动的边界处理模式（如钳位或镜像），可以简化边界条件的代码。

**优化三：可分离卷积**
许多 2D 卷积核（如高斯核）是“可分离的”，即一个 K×K 的 2D 卷积可以分解为先进行一次 1×K 的行卷积，再进行一次 K×1 的列卷积。这使得计算复杂度从 O(N²K²) 降低到 O(2N²K)，当 K 较大时，可以带来数倍的性能提升。NVIDIA 的 `convolutionSeparable` 示例就精确地演示了如何结合分块、常数内存和可分离特性，来实现一个高度优化的二维卷积。
