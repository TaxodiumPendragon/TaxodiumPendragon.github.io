本讲将深入探讨异构计算系统的编程方法，重点关注当前人工智能领域最主流的 CPU+GPU 协同计算模式。

- 首先理解构成异构系统的基本要素，即主机（Host）、设备（Device）以及它们之间的互连（Interconnect），
- 重点学习如何为 GPU 上的核心计算单元——CUDA 核心——编写程序。
- 关于 Tensor 核心的编程，将在后续课程中展开。

## 1 异构计算系统：主机、设备与互连

一个典型的异构计算系统由主机和设备两部分构成。通常情况下，主机指的是系统的中央处理器（CPU），它负责处理串行任务、操作系统调度和整体逻辑控制。设备则通常指专门的加速器，例如图形处理器（GPU）、张量处理器（TPU）或其他专用处理器（统称为 XPU），它们擅长执行大规模的并行计算任务。

主机与设备之间，以及设备与设备之间的协同工作，离不开高效的互连技术。
*   主机与设备间的互连（host-dev）：主要通过 PCIe 总线进行连接。近年来，英伟达也推出了 NVLink-C2C（Chip-to-Chip）技术，在像 Grace-Hopper 超级芯片这样的集成系统上，提供了远超 PCIe 带宽的 CPU-GPU 直连通道。
*   设备与设备间的互连（dev-dev）：除了可以通过主板上的 PCIe 交换机进行通信外，更常见的是通过专用的高速互连技术，如 NVLink，来实现 GPU 之间的直接数据交换。在更大型的集群中，还会用到支持远程直接内存访问（RDMA）的高性能网络技术。

AI 硬件的形态是多种多样的，从云端数据中心的 NVIDIA DGX A100 服务器，到边缘端的 NVIDIA Jetson AGX Orin 模块，再到移动端的 iPhone 手机，乃至物联网设备上的 Arduino Nano 33 开发板，构成了从云到端的完整硬件谱系。这些不同形态的硬件，其内部 AI 芯片的集成方式也有所不同。

AI 芯片的集成形态主要有两种。第一种是独立的 AI 芯片，以 DGX A100 为例，它在一块主板上集成了两颗 AMD CPU 作为主机，以及八块通过 PCIe 和 NVSwitch 互连的独立 A100 GPU 作为设备。这种板级集成方式提供了强大的扩展性。第二种是集成的 AI 芯片，也称为片上系统（SoC），以英伟达的 Thor 芯片为例。它在单一硅片上集成了高性能的 ARM CPU 核心、Blackwell 架构的 GPU 核心、以及各种 I/O 和多媒体处理单元。这种片内集成方式通过共享内存控制器和内部高速总线，提供了极高的能效和极低的通信延迟，但其可扩展性有限。

无论采用哪种集成方式，其核心都是主机 CPU 与一个或多个设备 XPU 的异构集成。它们之间的通信协议，如 PCIe 和 NVLink，以及内存一致性模型，是理解和驾驭这些系统的关键。

### 互连技术之 PCIe

PCI Express (PCIe) 是目前应用最广泛的计算机扩展总线标准。截至 2025 年，市场的主流是 PCIe 4.0，而最新的设备已经开始支持 PCIe 5.0。PCIe 通过“通道”（Lane）来传输数据，每个通道包含一对用于发送（TX）和接收（RX）的差分信号线。通道的数量决定了总带宽，常见的配置有 x1、x4、x8 和 x16。例如，一块 PCIe 4.0 x16 的 GPU，其理论双向带宽可以达到 64 GB/s。几乎所有的高性能设备，如 GPU、FPGA、NVMe SSD 和高速网卡，都通过 PCIe 接口连接到主板的 CPU 或芯片组上。

在 AI 计算中，PCIe 扮演着至关重要的角色。
*   在主机与 GPU 的连接中，主机通过 PCIe 向 GPU 发送指令（例如要执行的 CUDA 核函数）以及计算所需的数据（例如训练数据、模型权重）。计算完成后，GPU 再通过 PCIe 将计算结果（例如梯度、推理输出）以及状态信息返回给主机。传统的数据传输流程需要两次拷贝：首先数据从 NVMe 硬盘通过直接内存访问（DMA）拷贝到主机内存，然后再从主机内存拷贝到 GPU 显存。为了消除这一瓶颈，英伟达推出了 GPUDirect Storage 技术，它允许数据直接从 NVMe 硬盘通过 PCIe 交换机传输到 GPU 显存，绕过了主机内存，从而显著提升了数据加载效率。
*   在 GPU 与 GPU 的连接中，早期的多 GPU 系统通过 PCIe 进行通信。传统方式下，一个 GPU 的数据需要先拷贝回主机内存，再由主机内存拷贝到另一个 GPU，效率低下。GPUDirect Peer-to-Peer (P2P) 技术允许在同一 PCIe 根联合体下的 GPU 之间直接通过 PCIe 交换机进行数据传输，避免了主机的中转。

### 互连技术之 NVLink

尽管 PCIe 的带宽在不断提升，但它仍然是多 GPU 通信的主要瓶颈。为了解决这个问题，英伟达在 2016 年随 P100 GPU 推出了 NVLink 技术。NVLink 是一种专为 GPU 间高速互联设计的点对点串行通信协议。第一代 NVLink 的总带宽就达到了 160 GB/s，是当时 PCIe 3.0 x16 的五倍。

从第一代到最新的第五代，NVLink 的技术规格（如每 lane 速率、端口数）不断迭代，使得每颗 GPU 的总互连带宽从 160 GB/s 暴涨至 1800 GB/s。这种超高带宽的互连对于需要频繁进行数据交换的多 GPU 并行训练任务（如模型并行和流水线并行）至关重要。

## 2 主机与设备的交互编程模型

在 CUDA 编程中，CPU 和 GPU 拥有各自独立的内存地址空间。因此，程序需要显式地管理数据在这两个空间之间的分配与传输。一个典型的、不使用统一内存（Unified Memory）的 CUDA 程序流程如下：

1.  在主机端，使用 `malloc` 或 `new` 分配主机内存。
2.  在设备端，使用 `cudaMalloc` 分配 GPU 的全局内存（显存）。
3.  使用 `cudaMemcpy` 函数，将数据从主机内存拷贝到设备内存。这是一个阻塞操作，CPU 会等待拷贝完成。
4.  主机调用一个核函数（Kernel），`cudaLaunchKernel`，并将指向设备内存的指针作为参数传入。核函数是在 GPU 上并行执行的计算任务。这个调用是异步的，主机会立即返回，继续执行后续代码。
5.  由于核函数启动是异步的，如果主机需要等待 GPU 计算完成，则必须调用 `cudaDeviceSynchronize` 进行显式同步。
6.  再次使用 `cudaMemcpy`，将计算结果从设备内存拷贝回主机内存。
7.  最后，分别使用 `cudaFree` 和 `free` 释放设备和主机内存。

自 CUDA 6.0 起，引入了统一内存（Unified Memory）模型，它极大地简化了编程。在这种模型下，程序员只需调用一次 `cudaMalloc`（或 `cudaMallocManaged`），系统就会创建一个可以在 CPU 和 GPU 之间共享的内存池。数据在主机和设备之间的迁移由 CUDA 驱动程序根据页错误（Page Fault）机制自动处理，对程序员透明。这虽然带来了编程上的便利，但自动迁移可能会引入不易察觉的性能开销，因此在追求极致性能的场景下，显式内存管理依然是必要的。

## 3 CUDA 核心编程基础

### GPGPU 的演进之路

通用图形处理器（GPGPU）的概念，即将 GPU 用于通用科学计算，其发展根植于图形硬件的演进。传统的 GPU 采用的是固定的图形渲染管线，包含专门处理顶点（Vertex）、几何（Geometry）和像素（Pixel）的独立核心。这种设计的弊端在于，当渲染任务的瓶颈在某个特定阶段时（例如，一个场景有大量的几何细节但像素处理简单），其他阶段的核心就会处于闲置状态，造成硬件资源的浪费。

为了解决这一“利用率不足”的问题，业界提出了统一着色器核心（Unified Shader Cores）的革命性架构。从 ATI 的 Xenos 芯片（用于 Xbox 360）和 NVIDIA 的 GeForce 8800GTX 开始，GPU 不再区分顶点、几何和像素核心，而是采用大量同构的流处理器（Streaming Processor），这些处理器可以根据任务需求灵活地执行任何类型的着色程序。这一架构上的统一，为将 GPU 用于非图形任务打开了大门。

在 CUDA 出现之前，研究者们已经开始探索 GPGPU 的可能性，但过程异常艰辛。他们需要将自己的科学计算问题（如矩阵乘法）伪装成图形渲染任务，例如将矩阵编码为纹理（Texture），将计算过程编写成像素着色器（Pixel Shader），然后通过调用图形 API 来“渲染”出计算结果。这些早期工作虽然证明了 GPGPU 的巨大潜力，但也暴露了其编程的复杂性和局限性（如精度有限、内存接口不友好等），并促使业界思考和开发一个更通用的并行计算平台。最终，NVIDIA 在 2007 年推出了 CUDA，它提供了一个完整的并行计算架构和 C 语言扩展，正式宣告了 GPGPU 时代的来临。

### CUDA 并行模型：线程层级

CUDA 的核心是通过一个清晰的线程层级结构来表达和管理并行性。
*   **线程（Thread）**：是执行的最小单位。成千上万个线程同时执行同一个核函数。
*   **线程块（Thread Block）**：线程被组织成线程块。同一个块内的线程可以相互协作，它们可以通过高速的片上共享内存（Shared Memory）交换数据，并使用 `__syncthreads()` 同步点进行同步。一个线程块可以被组织成一维、二维或三维的结构。
*   **网格（Grid）**：一个或多个线程块组成一个网格。一个核函数的启动（Launch）实际上就是启动一个网格。网格也可以被组织成一维、二维或三维的结构。不同线程块之间的线程是无法直接同步的。

在核函数内部，每个线程都可以通过内建的只读变量来获知自己的身份标识：
*   `threadIdx`：线程在线程块内的索引（一维、二维或三维）。
*   `blockIdx`：线程块在网格内的索引（一维、二维或三维）。
*   `blockDim`：线程块的维度（即每个块包含的线程数）。
*   `gridDim`：网格的维度（即每个网格包含的块数）。

通过这些变量，我们可以计算出一个在整个网格中全局唯一的线程 ID。例如，对于一个一维网格和一维线程块的布局，全局 ID 的计算公式为 `int globalId = blockIdx.x * blockDim.x + threadIdx.x;`。这个全局 ID 通常被用来直接映射到需要处理的数据元素（如数组的索引）。

### GPU 执行模型：SIMD, SPMD, 与 SIMT

要理解 CUDA 代码如何在 GPU 上高效执行，需要区分几个相关的并行计算模型。
*   **SIMD（单指令，多数据）**：这是一种硬件架构。它指的是一个控制单元发出的单条指令可以同时在多个处理单元上对不同的数据执行。CPU 中的 AVX 指令集就是典型的 SIMD。
*   **SPMD（单程序，多数据）**：这是一种编程范式。程序员编写一个程序，这个程序会在多个独立的处理器上同时运行，每个处理器处理数据的不同部分。MPI 编程是典型的 SPMD。
*   **SIMT（单指令，多线程）**：这是 NVIDIA 提出的编程与执行模型，是 CUDA 的基石。SIMT 向程序员展现的是一个 SPMD 的模型：你只需编写一个核函数，它会被成千上万个线程独立执行。然而，在硬件执行层面，GPU 会将线程分组，每 32 个线程组成一个 **Warp**（在 AMD 硬件上称为 Wavefront，通常是 64 个线程）。同一个 Warp 内的所有线程在硬件上是以 SIMD 的方式执行的，即它们在同一时钟周期执行完全相同的指令，但作用于各自私有的数据。

SIMT 模型的巧妙之处在于，它结合了 SPMD 的编程简便性（程序员只需考虑单个线程的逻辑）和 SIMD 的硬件执行效率。GPU 的硬件调度器负责管理大量的 Warp，当一个 Warp 因为等待内存访问而停顿时，调度器可以立刻切换到另一个准备就绪的 Warp 继续执行计算，从而有效地隐藏了内存延迟，这是 GPU 实现高吞吐的核心机制。

## 4 CUDA 编程优化

编写功能正确的 CUDA 程序只是第一步，要发挥 GPU 的极致性能，必须进行深入的优化。优化通常是围绕着 GPU 的硬件资源进行的，包括流式多处理器（SM）、寄存器、共享内存和内存带宽。

### 提高占用率（Occupancy）

占用率是指一个 SM 上同时活跃的 Warp 数量与该 SM 理论上能支持的最大活跃 Warp 数量之比。更高的占用率意味着 SM 有更多的 Warp 可供调度，从而能更有效地隐藏内存延迟。占用率主要受以下三个因素的限制：
1.  **寄存器**：每个 SM 的寄存器堆大小是固定的。如果一个核函数中每个线程需要使用的寄存器过多，那么 SM 能容纳的总线程数（从而总 Warp 数）就会受限。例如，一个 SM 有 16384 个寄存器，如果一个核函数每个线程需要 35 个寄存器，那么这个 SM 最多只能同时运行 16384 / 35 ≈ 468 个线程，即使 SM 的硬件设计支持更多的线程。
2.  **共享内存**：每个 SM 的共享内存容量也是有限的。线程块（Block）是共享内存的分配单位。如果每个线程块需要使用的共享内存过多，SM 能同时容纳的线程块数量就会减少，从而限制了活跃 Warp 的总数。
3.  **线程/块数量限制**：硬件本身对每个 SM 能容纳的最大线程数和最大线程块数有物理上限。

这三个因素中，最严格的那个将成为占用率的瓶颈。优化时，可以通过减少每个线程的寄存器使用量（例如，通过优化代码逻辑或利用编译器选项）或减少每个块的共享内存使用量，来提升 SM 能同时调度的 Block 和 Warp 的数量，从而提高占用率。NVIDIA 的 Nsight 工具提供了占用率计算器，可以帮助开发者直观地分析和权衡这些因素。

### 处理分支分化（Divergent Control Flow）

由于同一个 Warp 内的 32 个线程在硬件层面是同步执行同一条指令的，如果代码中存在条件分支（如 `if-else`），并且 Warp 内的线程根据各自的数据走向了不同的分支，就会发生“分支分化”。此时，硬件会串行地执行 `if` 代码块和 `else` 代码块。当执行 `if` 块时，那些选择了 `else` 的线程会被硬件“屏蔽”（masked），不执行任何操作，反之亦然。这种串行化执行和线程屏蔽会造成大量的计算资源浪费，是性能的一大杀手。

处理分支分化的核心硬件机制是**断言（Predication）**。对于每个线程，都有一个断言寄存器。当遇到分支时，硬件会为 Warp 内所有线程执行两个分支的指令，但只有断言为真的线程才会将计算结果写回。

为了避免性能损失，编程时应尽量减少或避免 Warp 内的分支分化。一种常见的优化策略是重新组织数据或计算逻辑，使得同一个 Warp 内的所有线程尽可能地走相同的代码路径。

### 内存访问合并（Coalescing Memory Accesses）

全局内存（显存）的访问是 GPU 程序中最主要的时间开销之一。为了提高带宽利用率，GPU 访问显存的基本单位不是单个字节或单词，而是一个较宽的内存段（例如 32 字节或 128 字节）。**内存访问合并**指的是，当一个 Warp 中的 32 个线程恰好访问一个连续的、对齐的内存段时，硬件可以将这 32 个独立的访问请求合并成一次或几次宽体内存事务（transaction）来完成。这种合并访问可以充分利用内存总线的带宽。

反之，如果 Warp 内线程的访问模式是随机的、非连续的（即所谓的“跨步”访问），硬件就无法合并，必须产生大量的、低效的内存事务，导致实际可用带宽急剧下降。

因此，一个至关重要的优化原则是：**组织你的数据和线程映射，使得同一个 Warp 内的连续线程（即 `threadIdx.x` 相差为 1 的线程）访问全局内存中的连续地址**。在处理二维数据（如矩阵）时，如果数据是按行主序存储的，那么就应该让连续线程访问同一行中的相邻列，以实现合并访问。

### 共享内存与 bank 冲突

共享内存是位于 SM 芯片上的一小块高速读写存储器，其延迟远低于全局内存。它是线程块内线程间进行高效数据交换和协作的关键。为了支持高并发访问，共享内存被划分为多个等宽的存储体，称为 bank。理想情况下，一个 Warp 内的多个线程可以同时访问不同的 bank，从而实现并行读写。

**Bank 冲突**发生于当一个 Warp 内的多个线程试图同时访问同一个 bank 中的*不同*地址时。此时，硬件必须将这些访问串行化处理，从而产生延迟。冲突的严重程度取决于访问同一个 bank 的线程数量。

需要注意的是，有两种情况不会产生 bank 冲突：
1.  Warp 内所有线程访问不同的 bank。
2.  Warp 内所有线程访问同一个 bank 中的*完全相同*的地址。这种情况会触发一次“广播”（broadcast），数据会被高效地分发给所有请求的线程。

因此，在使用共享内存时，需要精心设计数据布局和访问模式，以避免或减少 bank 冲突。
