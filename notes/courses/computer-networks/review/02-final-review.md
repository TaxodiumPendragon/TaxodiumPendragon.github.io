## 22年考题

### 1. 

什么是排头阻塞“Head-of-line Blocking”。 在网络层与传输层中，哪个（些）场景中会出现 HOL 阻塞？ 请简要描述这些场景。（10 分）

HOL阻塞是指在应该队列中因为前面的数据包阻塞而导致后面的数据包也无法传递的情况

- 传输层：TCP多流复用中会出现排头阻塞，因为TCP要求有序性，丢一个前面的包后面的就得等待前面的重传成功才行，尽管可能是网页传图片这种数据流
- 网络层：路由器的输入端口会出现这种情况，在其存储转发机制里，因为开始的数据包在排队，导致后面的目标端口并不繁忙能够发送的数据包也无法发送

### 2
某同学从一台主机向同一个服务器请求 3 个图片 P1、 P2、 P3。使用HTTP 1.0、 HTTP 1.1、 HTTP 1.1-pipeline、 HTTP 2、 HTTP 3 这 5 种版本， HTTP 请求与响应的过程有什么不同？

HTTP1.0：是非持久连接，每次请求图片都要TCP三次握手重新建立连接
HTTP1.1：是持久连接，不需要过多TCP握手，可以建立连接发送三个请求，但必须有回应才能发下一个
HTTP1.1-pipeline：支持流水线机制，可以连续发多个图片请求，会按序响应
HTTP2：服务器可以主动推送消息检测客户端是否存活，允许应用层流量控制；*TCP多路复用，运行请求和响应交错，还可以自定义优先级*；
HTTP3：基于QUIC

### 3
> 三、 TCP 的可靠传输方案被认为是结合了回退 N（GBN）与选择重传（SR）两种方法。（15 分）

（1）请写出 TCP 中至少 2 个来自 GBN 的特性与至少 2 个来自 SR 的特性。每个特性显式说明是来自 GBN 还是 SR，并说明它的优点。（9 分）

- GBN：仅对最早发送的报文设置一个定时器(减少开销浪费)；采用累计确认(保证顺序性)
- SR：缓存失序的报文(避免多余的带宽浪费，不用重传多次)；仅在超时后重传最早未确认的报文(因为缓存了)

#### 2）请写出 TCP 可靠传输中至少 1 个在 GBN、 SR 都没出现过的特性，并说明好处。

- 传的ACK序号是期望收到的序号(反正PPT和书里是这么说的)，好处是方便重传
- 对字节建立序号而非报文(更符合传输场景)
- ACK放在数据包里，捎带过去
